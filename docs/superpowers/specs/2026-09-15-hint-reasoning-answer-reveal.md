# 확정 힌트 추론·정답 보기 애니메이션 설계

**날짜:** 2026-09-15  
**상태:** 설계 승인됨, 구현 계획 대기  
**기준 구현:** `einstein-riddle-app/` (`89a8ac6` 이후)

## 1. 목표

1. fact(확정) 힌트에 **왜 확정되는지**를 단서 인용 기반 2~3단계 추론으로 추가하고, **빨간색**으로 표시한다.
2. 「힌트 보기」 옆에 「정답 보기」를 두고, 포기 확인 후 타이머를 멈추며 빈칸·틀린 칸만 드래그형 비행 애니메이션으로 정답을 채운 뒤 조작을 잠근다.

## 2. 확정된 선택

| 항목 | 선택 |
|------|------|
| 정답 표시 | A — 보드를 정답으로 채우고 이후 조작 잠금 |
| 애니메이션 대상 | A — 이미 맞은 칸 유지, 빈칸·틀린 칸만 채움 |
| 추론 깊이 | B — 단서 원문 일부 인용, 2~3단계로 풀어 쓰기 |
| 구현 접근 | 힌트 생성기 확장 + UI 애니메이션 계층 |

## 3. 확정 힌트 빨간 추론

### 3.1 데이터

fact 단계 힌트 객체:

```js
{
  id: "h1-fact",
  stage: "fact",
  text: "3번 집의 음료는 우유로 확정할 수 있습니다.",
  reasoning: [
    "① 단서 2: 「…」 → …",
    "② 단서 5: 「…」 → …",
    "③ 따라서 3번 집 음료 = 우유",
  ],
  meta: { bundle, cat, val, houseIndex, clueIndices }
}
```

- `reasoning`은 길이 2~3 문자열 배열.
- 같은 묶음(clues 힌트)의 단서 번호를 우선 인용한다.
- 단서 원문은 앞뒤를 짧게 잘라 「」로 표시한다.

### 3.2 생성 규칙 (`hints.js`)

앵커 단서 `kind`별 템플릿:

| kind | 추론 골격 |
|------|-----------|
| `atHouse` | 단서 인용 → 해당 집·속성이 바로 정해짐 → 확정 문장 |
| `sameHouse` | 속성 A와 B가 같은 집 → answer로 집 위치 확정 → 확정 문장 |
| `nextTo` / `leftOf` | 위치 관계로 후보 축소 → 하나로 좁혀짐 → 확정 문장 |

answer에서만 고른 폴백 fact도, 관련 단서(같은 값·집)를 찾아 최소 2문장 추론을 붙인다.

### 3.3 UI

- 힌트 목록에서 `text`는 기존 색.
- `reasoning`이 있으면 그 아래 `<div class="hint-reasoning">`로 줄바꿈 표시, 색 `#ff7b8a`(기존 `--error`와 동일 계열).
- 색상만으로 구분하지 않도록 앞에 `①②③` 번호를 유지한다.

## 4. 정답 보기 + 애니메이션

### 4.1 UI·흐름

1. `#btn-reveal-answer`를 `#btn-hint` 오른쪽에 배치.
2. 클릭 → `confirm("포기하시겠습니까?")`
   - 취소: 변경 없음.
   - 확인: `game.stopTimer()` → `interactionLocked = true` → 채우기 애니메이션.
3. 종료 피드백: `포기했습니다. 정답을 표시합니다.`
4. 「새 문제」 또는 난이도 변경으로만 잠금 해제.

### 4.2 채우기 규칙

- `placement[cat][i] === answer[cat][i]` → 유지.
- 그 외(빈칸·틀림) → 애니메이션 큐에 추가.
- 틀린 칸의 기존 카드는 비행 시작 직전 풀로 복귀(또는 페이드아웃) 후 정답 카드가 목표 슬롯으로 이동.

### 4.3 애니메이션

- 고스트 카드: 출발(풀 해당 카드 또는 보드 하단) → 목표 슬롯, 350~450ms.
- 칸 간 딜레이 ~150ms (한 장씩).
- 진행 중 드래그·Undo·초기화·제출·힌트·정답 보기 비활성.
- 종료 후 보드를 정답 placement로 고정, 잠금 유지.

## 5. 상태 API (`state.js`)

추가:

- `isInteractionLocked(): boolean`
- `revealAnswer(): void` — 타이머 정지, 잠금, placement를 answer로 설정(애니메이션 중에는 main이 단계적으로 호출하거나, 완료 시 일괄 설정)
- `loadPuzzle` 시 잠금·정답 공개 플래그 초기화

권장 분리:

- 애니메이션 중: main이 칸 단위로 `moveCard`/`setCell`로 채우거나, 완료 시 `applyAnswerPlacement()`.
- 단순화: 애니메이션은 시각만 담당하고, 큐의 각 스텝마다 placement를 한 칸씩 정답으로 갱신·`renderAll`(드래그 바인딩은 잠금으로 무시).

## 7. 테스트

- fact 힌트에 `reasoning.length`가 2~3이고 단서 번호/「」 인용을 포함한다.
- `validateHints`가 reasoning 존재를 검사한다.
- HTML에 `btn-reveal-answer`가 있고, 힌트 버튼 옆에 위치한다.
- 포기 확인 후 타이머가 더 이상 증가하지 않는다(`stopTimer` + locked).
- 맞은 칸은 큐에 없고, 빈/틀린 칸만 대상이다(단위: 큐 계산 함수).

## 9. 성공 기준

1. 「확정할 수 있습니다」 힌트 아래에 빨간 2~3단계 추론이 보인다.
2. 「정답 보기」→ 포기 확인 → 타이머 정지 → 빈/틀린 칸만 순차 비행 채움 → 조작 잠금.
3. 새 문제로 잠금이 풀리고 정상 플레이가 가능하다.
