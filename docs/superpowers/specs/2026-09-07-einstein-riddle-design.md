# 아인슈타인 추론 게임 웹앱 — 설계 명세

**날짜:** 2026-09-07  
**상태:** 설계·구현 계획서 작성 완료 (난이도별 문제 생성 반영, 구현 대기)  
**대상:** 고등학교 2학년  
**제작 수준:** 게임/웹앱 초보 제작자 기준

---

## 1. 한 줄 요약

단서를 읽고 5채 집에 색·국적·음료·음식·동물 카드를 드래그해 배치한 뒤 제출로 검증하는, 서버 없는 HTML/CSS/JS 추론 수업용 웹앱. **난이도별로 알고리즘이 새 문제를 생성**해 학생이 여러 판을 풀 수 있다.

## 2. 학습 목표

학생이 **여러 단서의 제약을 결합**해 “가능한 배치”를 좁혀 가며, 최종적으로 유일한 해에 도달하는 추론 과정을 연습한다. 새 문제를 반복해 **같은 추론 전략을 다른 단서 조합에 적용**한다.

## 3. 합의된 요구사항

| 항목 | 결정 |
|------|------|
| 대상 | 고2 |
| 수업 형태 | 교사 시연 → 개인 실습 (혼합) |
| 입력 | 속성 카드 **드래그 앤 드롭**으로 집 그리드에 배치 |
| 학생 피드백 | **제출 후 틀린 칸 수만** 표시 (위치 비공개) |
| 교사 모드 (1차) | **같은 PC/화면**에서 비밀번호로 정답·보조 패널 |
| 퍼즐 | **알고리즘 생성** (집 5채 고정). 고전 1세트는 **폴백/데모** |
| 난이도 | **단서 개수**로 구분 (쉬움=많음, 어려움=적음). 정답 세계는 매 생성마다 다름 |
| 기술 | **HTML + CSS + JavaScript**만 (빌드 도구 없음) |
| MVP 포함 | 단서 하이라이트, Undo/초기화, 타이머(경과), 터치 드래그, **새 문제 생성** |
| MVP 제외 | 칸 정답 공개 힌트 버튼, 네트워크 진행 현황, 단서 편집기, 집 개수 가변 |

## 4. 수업 흐름

1. 교사가 화면 공유로 규칙·단서 읽기·드래그 시연 (약 5분).
2. 학생이 난이도(쉬움/어려움)를 고르고 **「새 문제」**로 판을 받은 뒤 개인 풀이.
3. 제출 → 틀린 칸 수 또는 클리어·소요 시간.
4. 원하면 「새 문제」로 다른 판 반복.
5. 필요 시 교사가 교사 모드로 **현재 판** 정답 확인 후 해설.

**장애 대비:** 인터넷 없이 로컬 실행. 생성 실패 시 폴백 퍼즐. 백업용 단서 인쇄물(폴백 세트) 가능.

## 5. 화면 구성 (단일 페이지)

| 영역 | 내용 |
|------|------|
| 상단 | 제목, 난이도, **새 문제**, 타이머, Undo, 초기화, 제출, 교사 진입 |
| 단서 | **현재 생성된** 단서 목록; 클릭 시 관련 집/속성 하이라이트 |
| 중앙 | 집 1~5 열 × 속성 행(색/국적/음료/음식/동물) 드롭존 |
| 카드 풀 | 아직 배치하지 않은 속성 카드 |
| 교사 패널 | 비밀번호 통과 후 **현재 판** 정답 그리드·비교 (기본 숨김) |

**접근성:** 집 색은 색상만으로 구분하지 않고 **집 번호 + 색 이름**을 병기한다.

## 6. 아키텍처

### 6.1 접근 방식

**모듈 분리된 정적 웹앱** (단일 HTML + `css/` + `js/`).  
퍼즐은 `generate.js`가 만들고, `solver.js`가 **유일해**를 검증한다.

### 6.2 디렉터리

```
einstein-riddle-app/
├── index.html
├── css/
│   └── styles.css
├── js/
│   ├── puzzle-data.js   # 속성값·라벨·폴백 정답/단서·생성 파라미터
│   ├── solver.js        # 단서 집합의 해 개수(0/1/2+) 계산
│   ├── generate.js      # 랜덤 세계 + 단서 생성(난이도별 목표 개수)
│   ├── state.js         # 현재 퍼즐·배치·Undo·타이머·난이도
│   ├── drag-drop.js
│   ├── clues.js
│   ├── teacher.js
│   ├── validate.js      # 현재 정답 대비 틀린 칸 수
│   └── main.js
├── tests/
│   └── run-tests.html
└── README.md
```

### 6.3 데이터 흐름

1. 시작/「새 문제」→ `generatePuzzle(difficulty)` → `{ answer, clues }`  
2. `state.loadPuzzle(...)` 후 배치·히스토리·타이머 초기화(새 문제는 타이머 리셋)  
3. 드래그로 state 갱신 → UI 리렌더  
4. 제출 시 `validate`가 **현재 answer**와 비교 → 틀린 개수만 표시  
5. 교사 모드는 **현재 answer** 표시  

### 6.4 모듈 책임

| 파일 | 하는 일 | 의존 |
|------|---------|------|
| `puzzle-data.js` | 값·라벨·폴백·`DIFFICULTY_TARGETS` | 없음 |
| `solver.js` | `countSolutions(clues, limit)` | puzzle-data |
| `generate.js` | `generatePuzzle(difficulty)` | puzzle-data, solver |
| `state.js` | 현재 퍼즐+플레이 상태 | puzzle-data |
| `validate.js` | `grade(placement, answer)` | — |
| `drag-drop.js` / `clues.js` / `teacher.js` / `main.js` | UI | state 등 |

## 7. 난이도별 문제 생성

### 7.1 알고리즘 (합의: 방식 B + 난이도=단서 수)

1. 각 카테고리 값을 집 1~5에 **무작위 순열**로 배치해 정답 세계 `answer` 생성.  
2. 템플릿으로 **참인 단서 후보 풀** 생성:
   - 같은 집: 「A는 B이다」(두 속성 동거)
   - 위치: 「N번 집에 A가 있다」
   - 이웃: 「A는 B의 옆집에 있다」
   - 왼쪽: 「A는 B의 왼쪽에 있다」(바로 옆 또는 왼쪽 어딘가 — **바로 옆**으로 고정)
3. 단서를 섞은 뒤, 솔버로 **해가 정확히 1개**가 되도록 집합을 조절:
   - 먼저 유일해가 될 때까지 단서 추가
   - 이후 **목표 개수에 가깝게** 불필요한 단서를 제거하되 유일해 유지
4. 한국어 `text`와 하이라이트용 `houseIds` / `categories` / `values` 메타데이터 부여.

### 7.2 난이도 목표

| 난이도 | 목표 단서 수 | 비고 |
|--------|--------------|------|
| 쉬움 (`easy`) | **12~15** | 유일해 전제, 가능하면 상한에 가깝게 |
| 어려움 (`hard`) | **8~11** | 유일해 유지하며 하한에 가깝게 축소 |

생성 중 목표 구간을 못 맞추면 **유일해인 집합**을 채택하고, 단서 수가 목표와 다르면 UI에 “이번 판 단서 N개”만 표시(실패로 보지 않음).  
**완전 실패**(유일해 불가) 시 최대 **20회** 재시도 후 `puzzle-data` 폴백 퍼즐 로드 + “기본 문제로 시작합니다” 안내.

### 7.3 UI·상태 규칙

- 「새 문제」: 확인 대화상자 → 현재 난이도로 생성 → 배치·Undo 비움 → **타이머 리셋**.  
- 난이도 변경: 확인 후 해당 난이도로 **즉시 새 문제 생성**(숨김 단서 방식이 아님).  
- 초기화: 배지만 리셋, **같은 문제·타이머 유지**.  
- 채점·교사 정답은 항상 **현재 로드된 answer**.

### 7.4 성능

브라우저 메인 스레드에서 생성. 목표: 보통 **2초 이내**. 초과 시 재시도/폴백. Web Worker는 1차 범위 밖.

## 8. 플레이·검증 규칙

### 8.1 배치

- 슬롯: 5집 × 5속성 = 25.
- 카테고리당 집마다 카드 최대 1개.
- 찬 슬롯에 드롭 시 **교체**(맞바꿈).
- 풀 ↔ 집 양방향. 화면 밖 드롭 → 원위치.

### 8.2 Undo / 초기화

- Undo: 직전 배치 변경 (상한 30).
- 초기화: 확인 후 배지→풀, **타이머 유지**, 문제는 유지.

### 8.3 타이머

- 첫 드래그 시 시작. 제출 시 정지. **새 문제** 시 리셋.
- 제한 시간 강제 종료는 2단계.

### 8.4 제출 (학생)

- 빈 칸 있으면 거부 + 안내.
- 오답: `틀린 칸 수 = N`만.
- 정답: 축하 + 소요 시간.

### 8.5 교사 모드

- 비밀번호 `teacher2026` (README에만 안내).
- **현재 생성 판** 정답·현재 배치 비교·단서 전체.
- 네트워크 진행 집계 없음 (2단계).

## 9. 퍼즐 콘텐츠 방침

- 카테고리: 색·국적·음료·음식·동물 (흡연 없음).
- `VALUES`/`LABELS`는 `puzzle-data.js`에서 교체 가능.
- 폴백은 고전 얼룩말형 한국어 각색 1세트.
- README에 수업용·생성형임을 명시.

## 10. UI·반응형

- 데스크톱(프로젝터) 우선, 태블릿 터치 드래그.
- 좁은 화면: 단서·그리드 세로 스택.
- 생성 중에는 「새 문제」버튼 비활성 + “문제 만드는 중…” 표시.

## 11. 실행·배포

1. `npx serve` 등 정적 서버 권장.  
2. USB 폴더 복사 배포.  
3. 로그인·DB 없음.

## 12. 에러·엣지 케이스

| 상황 | 동작 |
|------|------|
| 불완전 배치 제출 | 막기 + 안내 |
| 드래그 중 이탈 | 원위치 |
| 난이도 변경 / 새 문제 | 확인 후 재생성·진행 초기화 |
| 생성 실패 | 재시도 후 폴백 |
| 잘못된 교사 비밀번호 | 오류, 패널 비개방 |
| Undo 없음 | 버튼 비활성 |

## 13. 테스트 계획 (수업 전 수동)

- [ ] PC: 드래그, Undo, 초기화, 제출
- [ ] 태블릿: 터치 드래그
- [ ] 「새 문제」를 쉬움/어려움 각각 3회 이상 → 단서 수·내용이 달라지는지
- [ ] 생성 판을 정답으로 채워 제출 → 클리어 (교사 패널 정답 이용)
- [ ] 일부 오답 → 개수만 표시
- [ ] 교사 모드: 현재 판 정답만 노출
- [ ] 프로젝터 가독성

## 14. 초보 제작자 체크리스트

- [ ] 학습 목표 1문장 유지
- [ ] MVP / Non-goals 준수
- [ ] 속성 문구는 `puzzle-data.js`만 수정
- [ ] 생성·솔버는 테스트 페이지에서 먼저 검증
- [ ] 시연 스크립트에 「새 문제」포함
- [ ] 오프라인 실행 + 폴백 인쇄 백업
- [ ] 색+번호/이름 병기
- [ ] 교사 비밀번호를 학생 자료에 넣지 않음

## 15. Non-goals (2단계 이후)

- 교실 LAN / 온라인 진행 대시보드
- 교사용 단서·속성 편집기
- 칸 단위 정답 공개 힌트
- 제한 시간 강제·랭킹 서버
- 계정·클라우드 저장
- 집 개수 가변(3·4채)
- Web Worker 생성
- React 등 빌드 툴체인

## 16. 성공 기준

1. 시연 후 학생이 드래그·제출·**새 문제 반복** 가능  
2. 서버 없이 HTML/CSS/JS만으로 동작  
3. 생성 문제는 **유일해**이며 난이도에 따라 단서 수 경향이 다름  
4. 학생은 오답 위치를 제출 결과만으로 알 수 없음  
5. 교사는 같은 기기에서 **현재 판** 정답을 열어 해설 가능
